# 轨检数据定义

- CSV 表头 `event_id,run,kind,at,odo_mm,ref,grade`。ID、车次、基点和缺陷类别都是字符串。`kind` 为 `anchor` 或 `defect`。时间须带偏移，转换为 UTC。测距与标称里程以整数毫米记录，`grade` 为 1–3。空字符串与哨兵均隔离，空文件、全空白、仅表头分别报错。来源行号按 CSV 记录起行计。
- 列名支持固定字段重排。相同 `event_id` 若规范化后字段均相同则只计一次，冲突时该组全部隔离。先以文件顺序判断各车次 900 秒迟到窗口，再按 UTC 排序。空白行单列原因，重复表头单独记段。
- 测绘表列出 `ref`、`chain`、`station_mm` 与计划半开区间。匹配按车次与测绘基点取最高等级。最高等级内位置或时间冲突则留缺，完全相同取最早文件行。
- 时间与测距都以左闭右开分配相邻标定点；缺右端、超过 120 秒、不同链或两端测距不递增时不复位。区间中测距倒走的事件单独隔离。标称里程按端点进行线性插值，半毫米按 HALF_UP 取整。下行标称里程可以递减。
- 缺陷按链号、类别、位置排序，距离群起点最多 5000 mm 才并入，保留全部报文编号及行号。不同链的相同标称数值彼此独立。
- 覆盖按链把计划区间和有效区间各自求并集，再求交。重复覆盖是裁剪到计划后的原始长度与已映射长度之差。缺证片段带相交断档原因或 `NO_COVERAGE`。输入报文数等于采信、隔离和重复之和。
- 归档批次键为采信与隔离结论、测绘表、参数和规则版本的 SHA-256。认定批次时先抹去行号，并把可解析的时间统一写成 UTC：同一趟巡检换个列序、换个时区写法或整体错行仍是同一批，复用原快照而不重签。采信相同但隔离记录不同则属不同批。`input_sha256` 只是其中一份送达原件的字节摘要，不参与批次键。
- 每份送达原件按自身字节摘要单独登记，同一批次可以有多份原件。签发前冻结当时已登记的原件集合，签发后新到的复送件只追加登记，不改已签证据单。批次重跑或复送不新增同一原件的登记。
- 签发摘要为固定 JSON 序列化后的 SHA-256，可复算文件完整性。证据单同时给出快照行号到每份原件行号的对照，查证时按收到的原件找行号，结论仍以快照为准。单次写入失败整体回滚，可原样重试。
- 上传限制 2 MiB。UTF-8 BOM、UTF-8 与 GB18030 文件按顺序解码。测绘表随部署发布。归档无外部电子证书服务。
